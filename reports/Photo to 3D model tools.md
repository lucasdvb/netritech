# Open the proxy, then rent the GPU

Claude Code in this container can produce good GLB, OBJ or STL models from one photo, but only by calling a hosted model. With 4 vCPUs, no GPU and 15 GB of RAM, the open-source models that come close to commercial quality (TRELLIS.2, Hunyuan3D-2.1) cannot run here. The real limit, though, is the egress proxy rather than the hardware. Every 3D vendor tested (Meshy, Tripo, Rodin, fal, Replicate, Stability, Tencent) is refused at the proxy. Hugging Face model weights still fail because they redirect to `*.hf.co`. KIE AI, the one provider that is reachable and already set up, has no 3D models. So the decision comes down to which host to allowlist. The **official Meshy MCP server or the Meshy plugin in the Anthropic Directory** is the cleanest choice for a Claude-native default: one key, one host, and GLB/OBJ/STL/FBX/3MF output plus print repair. **fal.ai's hosted MCP** gives the widest choice of models and the lowest prices from one key (Hunyuan3D, TRELLIS 2, Rodin, Meshy, Tripo, from about $0.05 to $1.30 per mesh). **Figma Weave** is the only route that needs no allowlist change, because it runs through the Figma connector already in this session, but the user first has to link their Figma account to Weave. With no network change at all, the only free option today is a 2.5D depth relief. Allowlisting `*.hf.co` makes the CPU-feasible open models TripoSR and Stable Fast 3D usable, at draft quality. Every paid run below needs the user's explicit approval each time, under the project's generation rule.

## The proxy decides what works, not the CPU

Probes from this container on 7 October 2026 set the limits. **Reachable:** `api.kie.ai`, `pypi.org`, `registry.npmjs.org`, `github.com`, GitHub Releases downloads, `raw.githubusercontent.com`, and now `huggingface.co`. The user has allowlisted it: it returns HTTP 200, and small files such as TripoSR's `config.yaml` download. **Still refused (HTTP 403 on CONNECT):** `api.meshy.ai`, `api.tripo3d.ai`, `platform.tripo3d.ai`, `hyperhuman.deemos.com` and `api.hyper3d.com` (Rodin), `fal.ai`, `fal.run`, `queue.fal.run`, `mcp.fal.ai`, `api.replicate.com`, `mcp.replicate.com`, `api.stability.ai`, the Tencent Hunyuan endpoints, `api.3daistudio.com` and `download.pytorch.org`. One gap matters for local models. Large Hugging Face weight files redirect to **`us.aws.cdn.hf.co` (HF's Xet/CDN), which the proxy still rejects**, so `*.hf.co` must be allowlisted before any model weights can download. These results come from curl probes and the proxy's own status page in this session, not from a published source.

The fix is the same for every vendor. Add the API host, and the host that serves the result files, under the cloud environment's Network access → Allowed domains ([Claude Code docs: cloud environments](https://code.claude.com/docs/en/cloud-environments#network-access)). The result-file hosts for each vendor (for example fal's media CDN) were not verified. Expect to add a second host after the first test run returns a download URL that fails. This also covers MCP servers. A local stdio MCP server, a skill that runs a CLI, and a remote MCP added with `claude mcp add --transport http` all send traffic from the container, so all of them hit the same proxy. A remote MCP added as a claude.ai custom connector is routed through Anthropic's own MCP proxy instead, and it might avoid the container's allowlist. That has not been tested.

## Meshy and Rodin ship first-party Claude integrations; KIE offers nothing

The Anthropic Directory, which this org can see, has exactly one first-party photo-to-3D plugin: **Meshy**, a partner-tier plugin (v0.6.0) whose components are only skills (`meshy-3d-generation`, `meshy-3d-printing`, `meshy-openclaw`). The skills drive the Meshy CLI, export **GLB, OBJ, STL and FBX**, and log in with OAuth or a `MESHY_API_KEY` ([meshy-dev/meshy-3d-agent](https://github.com/meshy-dev/meshy-3d-agent)). For an MCP route, Meshy publishes **`@meshy-ai/meshy-mcp-server`** (npm 0.6.0, updated 5 October 2026). It has 24 tools, including `meshy_image_to_3d`, multi-image-to-3D, remesh, retexture, rig, animate, convert, UV-unwrap, and a 3D-printing suite with printability analysis and repair. To install it: `claude mcp add-json meshy '{"command":"npx","args":["-y","@meshy-ai/meshy-mcp-server"],"env":{"MESHY_API_KEY":"msy_..."}}'` ([GitHub](https://github.com/meshy-dev/meshy-mcp-server); [npm](https://registry.npmjs.org/@meshy-ai/meshy-mcp-server/latest)). Meshy image-to-3D with Meshy-6 costs **20 credits untextured or 30 textured** ([Meshy API pricing](https://docs.meshy.ai/api/pricing)). The USD price per credit could not be confirmed, because the pricing page is blocked from here.

Deemos publishes the official **Rodin3D Skills** as a Claude Code plugin marketplace. Install it with `/plugin marketplace add DeemosTech/rodin3d-skills` and then `/plugin install rodin3d-skill@rodin3d-skills`. It takes one to five images, needs `HYPER3D_API_KEY`, and exports **GLB, OBJ, FBX, STL and USDZ** ([DeemosTech/rodin3d-skills](https://github.com/DeemosTech/rodin3d-skills)). Rodin's direct API requires a **Business plan from about $120 a month** ([3D AI Studio API roundup](https://www.3daistudio.com/blog/best-3d-model-generation-apis-2026)), so for occasional use it is cheaper through fal.

Tripo's official MCP is not suitable here. [VAST-AI-Research/tripo-mcp](https://github.com/VAST-AI-Research/tripo-mcp) is an alpha that only drives the Tripo Blender add-on. The practical headless option is the community **`tripo-ai-mcp-server`** (npm v1.1.0), with `image_to_3d` (it uploads local files automatically), `multiview_to_3d` and `get_task_status`, keyed by `TRIPO_API_SECRET` ([Glama](https://glama.ai/mcp/servers/@pasie15/tripo-ai-mcp-server)). Tripo's API charges about **$0.01 per credit: $0.20 untextured, $0.30 textured, with 2,000 free credits at sign-up** ([Tripo developer pricing](https://developers.tripo3d.ai/en/pricing), search snippet).

The **fal.ai hosted MCP** gives Claude one key for search, schema lookup, upload and inference across fal's whole catalog. Install it with `claude mcp add --transport http fal-ai https://mcp.fal.ai/mcp --header "Authorization: Bearer YOUR_FAL_KEY"` ([fal docs](https://fal.ai/docs/model-apis/mcp)). **Replicate's official hosted MCP** (`claude mcp add replicate https://mcp.replicate.com/sse --transport sse`) is the equivalent route to Replicate's older TRELLIS and Hunyuan 2.x ports ([Replicate MCP docs](https://replicate.com/docs/reference/mcp)). For Hunyuan3D direct from Tencent, there is a Tencent CloudBase MCP template with `submitHunyuanTo3DJob` and `queryHunyuanTo3DJob` ([CloudBase docs](https://docs.cloudbase.net/en/ai/mcp/develop/server-templates/cloudrun-mcp-hunyuan-3d)).

The rest of the field is thin or unsuitable. **[codeofaxel/Kiln](https://github.com/codeofaxel/Kiln)** (90 stars) chains image-to-3D into slicing and printing, which matters if STL for printing is the real goal. **[mordor-forge/trident-mcp](https://github.com/mordor-forge/trident-mcp)** wraps Tripo, Meshy and Rodin in one server but has only 5 stars. The directory plugin **CellCog** advertises a `3d-model-generation` skill, but it does not say which model it uses or whether it accepts photos. **Car Image API** only handles vehicles. The claude.ai connector registry has no image-to-3D connector, only a Three.js viewer and Trimble SketchUp (session catalog search). The MCP registry lists **three.ws**, which has a free tier for text or image to GLB, but its paid tools use x402 crypto payments and it does not say which model it uses ([MCP registry](https://registry.modelcontextprotocol.io/v0/servers?search=3d)). No MCP server exists for Stability, Luma, CSM or Sloyd.

**KIE AI cannot help.** Its marketplace lists 115 models from 25 providers, none of them 3D ([kie.ai market](https://kie.ai/market)). Its pricing page has no mesh line items ([kie.ai pricing](https://kie.ai/pricing)), and the user's own KIE skills list 3D as out of scope. **Blender MCP** is also the wrong primary tool here. [ahujasid/blender-mcp](https://github.com/ahujasid/blender-mcp) (about 30.2k stars; install with `claude mcp add blender uvx mcp-for-blender`, since the PyPI package was renamed) can call Tripo, Rodin and Hunyuan3D. But it needs a running Blender with its socket add-on, and the generation still happens on the same blocked cloud APIs. Headless Blender only becomes useful after generation, for conversion, decimation or renders, and the small headless forks such as [sandraschi/blender-mcp](https://github.com/sandraschi/blender-mcp) are immature. For conversion alone, Python's `trimesh` from PyPI can turn GLB into OBJ or STL without Blender.

## Figma Weave works today, after one account link

Figma Weave offers the most 3D models of any connected tool: **Rodin, Rodin V2, Trellis, Trellis 3D V2, Meshy V6, Hunyuan 3D, Hunyuan 3D V2.1 and Hunyuan 3D V3**, at **2 to 96 credits per run**. Trellis 3D V2 costs 30 credits, Rodin V2 36 and Meshy V6 96 ([Weavy 3D models comparison](https://help.weavy.ai/en/articles/12344357-3d-models-comparison), search snippet; the page date is unknown). Figma's own examples include turning three views of an object into a model you can rotate, using Rodin 3D V2 ([Figma blog](https://www.figma.com/blog/five-figma-weave-workflows/)). The `weave_find_model` and `weave_run_model` tools are already connected in this session, and their traffic goes through the connector rather than the container proxy. So this is the **only route that needs no allowlist change**. A read-only lookup returned that the user's Figma account is **not yet linked to Weave**. Linking it is a one-time step at [app.weavy.ai settings](https://app.weavy.ai/settings?section=profile). Three things remain unknown: the USD price of a Weave credit, whether Weave returns GLB or another format, and whether newer model versions have been added since the comparison table was written.

## Only TripoSR and Stable Fast 3D fit four CPU cores

Nearly every leading open-source model assumes CUDA. **TRELLIS needs a 16 GB+ NVIDIA GPU and TRELLIS.2 needs 24 GB+ with CUDA 12.4 kernels** ([TRELLIS.2](https://github.com/microsoft/TRELLIS.2)). Hunyuan3D-2.1 needs about 29 GB for shape plus texture ([Hunyuan3D-2.1](https://github.com/Tencent-Hunyuan/Hunyuan3D-2.1)). InstantMesh, CRM, Wonder3D, Unique3D, LGM and Era3D all depend on xformers, nvdiffrast or tiny-cuda-nn. The closest thing to a CPU port is a Mac port of TRELLIS.2, and it still needs about 18 GB peak memory, more than this box has. Two models remain realistic here.

| Model | License | CPU path | Expected on 4 vCPU / 15 GB | Main friction |
|---|---|---|---|---|
| [TripoSR](https://github.com/VAST-AI-Research/TripoSR) | MIT | torchmcubes CPU fallback; no CUDA-only kernels; int8 ONNX ports exist | Estimated tens of seconds to minutes, 4–8 GB RAM; draft mesh with vertex colours or baked texture | `transformers==4.35.0` pin on Python 3.13; weights on HF |
| [Stable Fast 3D](https://github.com/Stability-AI/stable-fast-3d) | Stability Community (free under $1M revenue) | Official: "CPU backend will automatically be used"; C++/OpenMP texture baker | Estimated 1–5 min, 6–10 GB RAM; UV-unwrapped textured GLB | Gated weights (HF token); `numpy==1.26.4` needs Python ≤3.12; swap `rembg[gpu]` for `rembg[cpu]` |
| [SPAR3D](https://github.com/Stability-AI/stable-point-aware-3d) | Stability Community | Official, but "really slow" | Borderline at 15 GB | Extra git dependencies |
| [Hunyuan3D-2mini](https://github.com/Tencent-Hunyuan/Hunyuan3D-2) shape only | Tencent community; **excludes EU, UK, South Korea** | Plain PyTorch shape stage; not documented for CPU | Probably several minutes, untextured | Texture stage needs compiled rasterizers |

The timing and memory figures are estimates. No public 4-vCPU benchmark exists for any of these, so verify them with one local test run. Two infrastructure problems apply to all of them. First, `download.pytorch.org` is still blocked, so torch must come from PyPI, where the 528 MB wheel pulls in several GB of CUDA libraries it will never use. TripoSR's ONNX export avoids torch entirely: about 430 MB for an int8 encoder, plus `onnxruntime`, a marching-cubes package and `trimesh` ([QtMeshEditor TripoSR ONNX](https://huggingface.co/fernandotonon/QtMeshEditor-triposr-onnx)). Second, every one of these models keeps its weights on Hugging Face, and they will not download until **`*.hf.co`** joins the allowlist. Even then, expect output at game-prop quality: a good silhouette and front, and a blurry, invented back side. None of them matches TRELLIS.2 or the commercial APIs.

One pipeline works today with no allowlist change and no credits. **rembg** (MIT, `pip install "rembg[cpu]"`) downloads its ONNX models from GitHub Releases ([rembg](https://github.com/danielgatis/rembg)). **Depth Anything V2 Small** (Apache-2.0, 99 MB ONNX, also on GitHub Releases) ([Depth-Anything-ONNX](https://github.com/fabio-sim/Depth-Anything-ONNX/releases/download/v2.0.0/depth_anything_v2_vits.onnx)) estimates depth in seconds on CPU. numpy and trimesh then displace a grid into a textured GLB/OBJ/STL. The result is a **2.5D relief**: only the front face, with no back side. It suits coins, plaques, bas-relief prints and Three.js parallax heroes, but not an object that has to rotate more than about 20 degrees ([Towards Data Science walkthrough](https://towardsdatascience.com/generate-a-3d-mesh-from-an-image-with-python-12210c73e5cc/)).

## Recommendations in priority order

**Start with Figma Weave** if the user wants a model this week with the least setup. Link the Figma account at the Weavy settings page, then run Trellis 3D V2 (30 credits) or Rodin V2 (36 credits) through `weave_run_model`. Each run needs explicit approval. Confirm the output format on the first run.

**Make Meshy the standing Claude Code integration** if 3D generation will be a repeated task. Enable the Meshy plugin from the Anthropic Directory, or add `@meshy-ai/meshy-mcp-server` with `claude mcp add-json`. Then allowlist `api.meshy.ai` and its asset host, and add `MESHY_API_KEY` to the environment's secrets. It is the only first-party option that covers generation, format conversion and 3D-print repair in one tool. That makes it the best default when STL output is the goal.

**Add fal for choice and price** if comparing models matters or cost per mesh must stay low. One key and the `fal.ai`/`fal.run`/`queue.fal.run`/`mcp.fal.ai` hosts open up Hunyuan3D (from about $0.05), TRELLIS 2, Rodin, Meshy 7.1 and Tripo P2. That makes fal the best tool for testing several models on the same photo, and the cheapest way to reach Rodin. Use the community Tripo MCP only when its 2,000 free credits or quad topology matter. Skip Rodin's direct API unless the user already pays for the Business plan.

**Allowlist `*.hf.co` only for free local experiments**, and pick TripoSR (simplest, MIT, ONNX option) or Stable Fast 3D (better textures; needs a gated-model token and a Python 3.12 venv). Use the rembg-plus-depth relief pipeline now, at no cost, for anything that only needs to look 3D from the front.

## Conclusion

GPU power is not what matters most in this container. The work is in choosing which network hosts to open and which bill to accept. Hosted APIs have moved the hard part off the machine, so Claude Code's job is mostly orchestration: background removal, upload, polling, format conversion with trimesh, and checking STL printability. These tasks run fine on four CPU cores. Two developments will matter for future choices. The connector route (Weave now, and possibly claude.ai custom connectors) avoids the container's allowlist completely. Prices now span about 25 times, from $0.05 Hunyuan runs to $1.30 Tripo P2 runs, so routing each job by object type matters more than picking one vendor. The biggest unknowns that could change these recommendations are Weave's real output format and credit price, the result-download host each vendor needs, and real CPU timings for TripoSR and SF3D. Each can be settled with one approved test run.
